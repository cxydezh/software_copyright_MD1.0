# 软著管理系统综合测试方案

## 测试目标

1. 验证Web端和桌面端的所有核心功能
2. 发现并记录系统bug
3. 验证数据完整性和一致性
4. 测试安全性和性能
5. 确保业务流程完整性

## 测试环境准备

### 环境配置要求

- **Web端**: Python 3.8+, MySQL 5.7+, Flask 3.0
- **桌面端**: Windows 10+, Tkinter, SQLite
- **浏览器**: Chrome最新版
- **网络**: Web端和桌面端需在同一局域网

### 启动顺序（重要）

1. **第一步**: 启动Web服务 `python run_web.py`
2. **第二步**: 启动桌面应用 `python run_desktop.py`

## 测试阶段划分

### 阶段1: Web端基础功能测试 (Web服务必须先运行)

#### 1.1 用户认证系统测试

- **测试点**: 用户注册、登录、登出、密码重置、邮箱验证
- **测试用户角色**: 普通用户、普通业务员、项目执行者
- **测试数据**: 
  - 管理员账户: admin@yiqichuang.com / admin123
  - 测试用户账户: 创建新用户测试注册流程
  - 测试员工账户: 创建不同权限的员工

#### 1.2 软件著作权业务流程测试

**完整流程节点**: 待确认 → 已确认 → 已立项 → 执行中 → 已完成 → 已上传 → 已获取流水号 → 证书完成 → 已结清 → 已归档

**测试场景**:

- 用户提交软件著作权申请
- 业务员确认并编辑申请
- 业务员立项审批
- 执行者接收并执行项目
- 执行者标记项目完成
- 更新流水号
- 上传证书（这个略过）
- 标记结清
- 项目归档

**测试数据**:

- 项目类型: 软件登记业务、软件设计与登记业务、软件部署与登记业务
- 申请人类型: 个人、事业单位、事业单位联合个人、自然人联合
- 优先级: 普通、加急、快速

#### 1.3 论文指导业务流程测试

**测试场景**:

- 用户申请论文指导服务
- 员工确认并分配执行者
- 论文状态更新: 初稿 → 修改中 → 已投稿 → 审稿中 → 已录用 → 已发表
- 文件上传与管理
- 项目结清与归档

**测试数据**:

- 项目类型: 论文指导、论文发表、学术咨询
- 服务等级: 基础服务、标准服务、高级服务
- 申请人类型: 个人学者、医疗机构、企业研发、联合申请

#### 1.4 专利申请业务流程测试

**测试场景**:

- 用户申请专利服务
- 员工确认并分配执行者
- 专利状态更新: 准备材料 → 已提交 → 受理中 → 审查中 → 授权 → 已发证
- 文件上传与管理
- 项目结清与归档

**测试数据**:

- 项目类型: 发明专利、实用新型专利、外观设计专利、PCT国际专利
- 申请人类型: 个人发明者、企业申请、科研院所、联合申请

#### 1.5 文件管理测试

- 上传各类型文件（身份证、统一社会信用代码证书、合同）
- 验证文件大小限制（16MB）
- 测试文件类型验证
- 测试文件下载功能

#### 1.6 权限管理测试

- 测试不同角色的访问权限
- 测试权限表配置: can_confirm, can_execute, can_manage, can_edit_paper, can_edit_patent
- 测试越权访问保护

#### 1.7 API接口测试

**桌面端专用API** (`/api/desktop/`):

- `/login` - 桌面端登录
- `/projects` - 获取项目列表
- `/update_project` - 更新项目状态
- `/update_serial_number` - 更新流水号
- `/sync_data` - 数据同步

### 阶段2: 桌面端功能测试 (依赖Web端运行)

#### 2.1 桌面端登录测试

- 测试使用Web端账号登录
- 验证只有执行者和管理员可登录
- 测试网络连接失败处理

#### 2.2 任务视图模块测试

**测试场景**:

- 查看"已立项"、"执行中"、"已完成"项目列表
- 创建项目文件夹
- 更新项目状态
- 查看项目详情
- 搜索项目（按申请者姓名、流水号、著作权人）
- 右键菜单功能（打开文件、打开文件夹）

#### 2.3 模板管理模块测试

- 添加新模板（复制文件夹）
- 编辑模板信息（名称、编程语言、IDE、数据库类型等）
- 删除模板
- 从模板创建项目文件

#### 2.4 材料管理模块测试

**测试三种材料类型**:

- 身份证复印件管理（姓名、性别、籍贯、身份证号）
- 统一社会信用代码证书管理（事业单位名称、有效期、法人代表）
- 合同管理（合同名称、参与人类型）

**测试操作**:

- 添加新材料文件
- 编辑材料信息
- 删除材料
- 文件命名验证（ID.名称格式）

#### 2.5 系统设置模块测试

- 配置各类文件夹路径
- 测试路径更改后的功能影响
- 验证默认路径创建

#### 2.6 Dialog窗体测试

- 身份证复印件Dialog（显示全部和最近10条）
- 统一社会信用代码证书Dialog（显示全部和最近10条）
- 合同Dialog（显示全部和最近10条）
- 双击复制文件到项目文件夹
- 选择显示详情

#### 2.7 流水号获取功能测试

- 点击按钮打开版权中心网站
- 模拟流水号更新（需要实际页面或mock数据）
- 验证流水号同步到服务器和本地数据库

#### 2.8 网站快捷访问测试

- 打开公司网站（http://192.168.31.56:5000）
- 打开版权中心网站（https://register.ccopyright.com.cn/login.html）
- 测试浏览器路径配置

### 阶段3: 数据同步与一致性测试

#### 3.1 Web端到桌面端数据同步

- Web端创建新项目，验证桌面端可见
- Web端更新项目状态，验证桌面端同步
- 测试同步延迟和失败处理

#### 3.2 桌面端到Web端数据同步

- 桌面端更新流水号，验证Web端同步
- 桌面端更改项目状态，验证Web端同步
- 测试网络断开时的数据缓存

#### 3.3 本地SQLite与MySQL数据一致性

- 验证本地项目表与服务器项目表数据一致
- 测试冲突解决机制
- 验证归档项目的数据完整性

### 阶段4: 安全性测试

#### 4.1 Web安全测试

- **XSS攻击测试**: 在输入框注入脚本
- **SQL注入测试**: 在登录和查询表单测试
- **CSRF测试**: 验证表单令牌
- **路径遍历测试**: 尝试访问系统文件
- **密码安全**: 验证密码哈希存储

#### 4.2 权限绕过测试

- 尝试以普通用户访问管理员功能
- 测试API端点的身份验证
- 测试文件访问权限

#### 4.3 会话管理测试

- 测试会话超时（24小时）
- 测试多设备登录
- 测试登出后的访问控制

### 阶段5: 性能与压力测试

#### 5.1 并发测试

- 10个用户同时登录
- 多个用户同时申请项目
- 多个执行者同时更新项目

#### 5.2 数据量测试

- 创建100+项目测试列表性能
- 测试大文件上传（接近16MB）
- 测试数据库查询性能

#### 5.3 响应时间测试

- 页面加载时间
- API响应时间
- 文件上传/下载速度

### 阶段6: 错误处理与异常测试

#### 6.1 网络异常测试

- 测试Web服务停止时桌面端行为
- 测试数据库连接失败处理
- 测试网络超时处理

#### 6.2 数据异常测试

- 测试必填字段为空
- 测试数据类型不匹配
- 测试非法字符输入

#### 6.3 文件系统异常测试

- 测试文件夹不存在时的创建
- 测试磁盘空间不足
- 测试文件权限问题

### 阶段7: 用户体验测试

#### 7.1 界面交互测试

- 测试按钮响应
- 测试表单验证提示
- 测试错误消息显示

#### 7.2 流程顺畅性测试

- 完整走完一个项目流程
- 记录每个步骤的用户体验问题
- 测试快捷键和右键菜单

#### 7.3 跨平台兼容性测试

- 测试不同浏览器（Chrome、Edge、Firefox）
- 测试不同分辨率
- 测试移动端访问

创建测试报告模板：

- **Bug ID**: 唯一标识
- **发现时间**: 时间戳
- **测试阶段**: 哪个测试阶段发现
- **严重程度**: 致命/严重/一般/轻微
- **Bug描述**: 详细描述
- **重现步骤**: 如何重现
- **预期结果**: 应该是什么
- **实际结果**: 实际发生什么
- **附件**: 截图或日志
- **状态**: 待修复/已修复/已验证

- 所有核心功能正常运行
- 三大业务类型完整流程可走通
- 无致命或严重级别bug
- 数据同步准确无误
- 安全测试无重大漏洞
- 性能满足实际使用需求

## 注意事项

1. **依赖关系**: 桌面端必须在Web端启动后才能运行
2. **网络配置**: 确保配置文件中的IP地址正确（192.168.31.56:5000）
3. **数据库**: MySQL和SQLite都需要正确初始化
4. **文件路径**: 桌面端默认路径为 D:/SoftwareCopyrightMS
5. **测试隔离**: 使用测试数据库，避免影响生产数据
